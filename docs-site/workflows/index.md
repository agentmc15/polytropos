# Workflows

Three walkthroughs, in the order most people need them. Each names real commands on all
three harnesses and links the skill page behind every step.

## [Route one task](first-route.md)

You are about to run something and you want to know what it will cost, and whether a
cheaper model would have done. Five minutes, spends nothing by itself, and it is the
habit the rest of this tool is built around. Start here.

## [Run a kit](run-a-kit.md)

The work is too big for one dispatch — a codebase review, a migration, a greenfield
build. Plan it once at the frontier tier, get an execution kit out, and let cheaper models
carry it task by task with verification between each one. This is the workflow the
repository exists for.

## [Measure the savings](measure-the-savings.md)

The kit finished and the cheap models seemed fine. Prove it: first-try pass rates, how
much of the cheap-model work survived review unchanged, and what the run actually cost
against an all-frontier counterfactual. Then use that evidence to pin the next kit's
models.

## Before you start

Every `python3 bin/…` command on these pages assumes your shell is in a polytropos
checkout — see [where you stand matters](../getting-started/index.md#where-you-stand-matters).
The concepts behind all three workflows are in [Concepts](../concepts/index.md); the
per-skill detail is in the [skills reference](../skills/index.md).
